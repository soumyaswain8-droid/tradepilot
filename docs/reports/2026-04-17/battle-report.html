The v5 Collapse — 95% Drop Day-over-Day

v5 went from +Rs 17,295 (92% win) yesterday to +Rs 781 (36% win) today

Four root causes

1. Shorting in a rising market (-Rs 3,566 on one stock)

v5 shorted ENRIN THREE times, lost all three: -Rs 1,098, -Rs 1,314, -Rs 1,154. Also lost JIOFIN shorts -Rs 318, TMPV -Rs 151.
Fix: Pre-market gap filter — if Nifty gap > +0.2%, disable all shorts for the day.

2. Crash wiped out morning gains (-Rs 487)

v5 crashed at 10:28 (NaN guard bug). Before crash, it had hit GODFRYPHLP target for +Rs 487 and deployed UNITDSPR. State save was pending — both were lost on restart.
Fix: Atomic state writes after every trade entry/exit, not per-cycle.

3. No same-stock re-entry block

After ENRIN short #1 hit SL, v5 re-entered ENRIN short. Hit SL. Re-entered again. Hit SL. No circuit breaker for repeated losses on same stock.
Fix: Block same-stock short re-entry for the day after 1 SL hit.

4. KALYANKJIL carry-over hit SL (-Rs 119)

Yesterday's open LONG KALYANKJIL @442.50 stopped out today at 427.65. Holding overnight added risk without commensurate reward.
Fix: Evaluate all carry-overs against opening gap before market open; exit losers proactively.
Long trades made money across all engines. Short trades lost money across all engines.

Top 5 Lessons for Tomorrow

#1. NaN guard bug in 5 files

v5, v5.4, v5.5, v5.6, v5.7 all had if price <= 0 which doesn't catch NaN (NaN<=0 is False in Python). Fixed to if not (price > 0). Root cause: copy-paste propagation.
Create utils/signal_guards.py with shared safe_qty(budget, price). One fix, all engines benefit.

#2. Shorts got destroyed in a rising market

v5 shorted ENRIN 3 times, lost 3 times for total -Rs 3,566. Same pattern in v5.6/v5.7. Regime was SIDEWAYS but Nifty gapped +0.38%.
Add pre-market gap filter: Nifty gap > +0.2% disables all shorts for the day.

#3. Laptop-in-bag is unreliable on macOS

Clamshell sleep killed all 5 paper-trade engines at ~16:15. Rust+Flask survived (launched via different shell paths).
Move engines to a $5/mo VPS (DigitalOcean/Hetzner). 24/7 uptime, no sleep issues.

#4. pmset silently failed

sudo pmset -a disablesleep 1 appeared to succeed but SleepDisabled remained 0.
Always verify with pmset -g | grep SleepDisabled showing 1 BEFORE trusting.

#5. State saved only at cycle end

v5 crashed at 10:28, lost GODFRYPHLP +Rs 487 win because state save was pending for the cycle.
Atomic state writes after every trade entry/exit, not per-scan.
