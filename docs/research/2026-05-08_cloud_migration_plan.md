## PART 5: ROLLBACK PLAN (If Monday Cloud Fails)

**Rollback time budget: 10 minutes**

### Emergency Rollback Procedure

1. **Stop cloud service** (30 seconds)
   - Render dashboard > Service > Suspend
   - Result: cloud-url returns 503

2. **Verify laptop is still running** (30 seconds)
   ```bash
   ./scripts/launch-market.sh --status
   ```
   - Should show: 7/7 engines, Rust OK, watchdog OK

3. **Repoint traffic if DNS was changed** (5 minutes)
   - If you added DNS CNAME: Point it back to laptop's static IP (if you set one)
   - If no DNS: Users access laptop directly via IP
   - Render DNS takes 5-10 min to propagate; use IP-based redirect in the meantime

4. **Verify laptop dashboard loads** (1 minute)
   - `curl http://localhost:5050/`
   - Dashboard should respond

5. **Telegram notification** (1 minute)
   - Send manual message: "⚠ Cloud rolled back. Running on laptop."

**Total rollback time: 5-10 minutes**

## PART 6: TOP 5 RISKS & MITIGATIONS

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| **DNS/SSL cert fails to issue** | Medium (20%) | High — dashboard unreachable | Keep laptop dashboard accessible as fallback; test DNS before cutover |
| **Flask crashes on cloud (Python version mismatch)** | Medium (25%) | High — dashboard down | Test Dockerfile locally on Mac + Linux; verify Python 3.11; check logs immediately |
| **Kite/yfinance blocks cloud VM IP** | Low (10%) | High (future) — no trades | IP whitelist NOW if using real APIs; test IP before adding real money |
| **Cloud disk full (logs grow too large)** | Low (15%) | Medium — errors on new logs | Implement log rotation; use Render's 1GB disk initially (sufficient for 1 week of logs) |
| **Timezone mismatch (cloud in UTC, laptop in IST)** | Medium (30%) | Medium — EOD timing wrong | Set TZ=Asia/Kolkata in cloud environment; test 15:35 auto-stop behavior Sunday |

**Critical mitigation: Keep laptop running in parallel for minimum 2 weeks, no matter what.**
