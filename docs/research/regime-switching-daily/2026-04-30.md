### Implementation takeaways for TradePilot Phase 2.2

1. **Rolling HMM refit cadence**: 63 trading days (~3 months) per the MDPI canonical. Our Phase 2.1 spec has weekly Monday refits — that's MORE frequent than literature. Consider relaxing to monthly to match the canonical and reduce overfit risk.

2. **Feature priority order** (informed by today's research):
   - Tier A (must, MDPI-validated): yield-curve proxy, gold-to-equity ratio, distance-from-200d-SMA
   - Tier B (TradePilot-specific): VIX India + 5d delta, FII/DII Z-score, USD/INR change, Bank-Nifty/Nifty ratio, breadth %
   - Tier C (event flags): is_expiry, mins_to_expiry, is_event_day
   - Total target: 30-40 features. MDPI used 63; for India we have less cross-asset data so 30-40 is realistic.

3. **No separate models needed** — confirmed twice now (yesterday's master + today's research). One LightGBM with regime probability features is the canonical pattern.

4. **Validation gates** — use the MDPI stack: walk-forward + block bootstrap + Deflated Sharpe Ratio + Probability of Backtest Overfitting. This is non-negotiable for TradePilot Phase 2.2 promotion.

5. **No production-ready open-source LightGBM regime-aware repo exists in 2026.** MarketRegimeNet is closest but small. **TradePilot Phase 2.2 will be a published-pattern + bespoke implementation**, not a fork. Plan for ~2-3 weeks of original engineering work, not "git clone and adapt".
