# Schedule snapshot — the 42 launchd jobs, as they actually run

Taken 2026-09-01. **This is a backup of live state, not the source of truth.**

## Why it exists

A migration survey found that ~34 of the 42 loaded job definitions existed **only** in
`~/Library/LaunchAgents`, generated by `scripts/team/cadence/_plist_gen.py` and never
committed. Losing the Mac — theft, disk failure, a bad OS upgrade — would have lost the
entire schedule with no record of what ran, when, or in what order. The engines and
research scripts were all in git; the thing that *makes them run* was not.

That is a durability gap independent of any cloud plan, which is why it was fixed
immediately rather than folded into the migration.

## What this is and is not

- **Is:** a point-in-time copy so the schedule can be reconstructed.
- **Is not:** the loaded configuration. Editing a file here changes nothing. launchd
  reads `~/Library/LaunchAgents`, and the generator can overwrite those at any time.

Three plists under `scripts/launchagents/` (outside `snapshot/`) are hand-maintained and
are the source for their jobs. Do not resolve a conflict by copying from here.

## Refreshing it

```sh
for f in ~/Library/LaunchAgents/com.tradepilot.*.plist \
         ~/Library/LaunchAgents/com.soumya.tradepilot*.plist; do
  case "$f" in *.bak*) continue;; esac
  cp "$f" scripts/launchagents/snapshot/
done
```

Worth re-running whenever the cadence generator adds or changes a job.

## Restoring

Copy back into `~/Library/LaunchAgents`, then `launchctl load` each. Check the paths
first: several embed `/Users/soumyaswain/anaconda3/bin/python3` and the absolute repo
root, so a restore onto a different machine or user needs those rewritten.

## Related

`scripts/orphaned/` holds three scripts that jobs here execute from
`~/Library/Application Support/tradepilot/` — outside the repo entirely. Two had no copy
in git at all; `eod-comparison-daily.py` had a mirror that has since diverged. Read
`scripts/orphaned/README.md` before trusting either copy.
